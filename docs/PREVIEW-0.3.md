# Preview 0.3 verification and Windows checklist

Implemented: short footer stages and per-image progress; file-only diagnostics; verified Microsoft direct-link media downloads; automatic ESD/SWM cache preparation; all-edition export and complete split-set joining; edition deletion and eligible offline upgrades; setup-template ISO conversion; VHD/VHDX DISM mounts; deployed/live package and feature servicing; and a compatibility-gated interactive Windows Setup wizard.

The core harness passed 62 checks on Linux using local files and simulated HTTP handlers. New coverage includes structured progress parsing, refusing online-only misuse of offline operations, unknown targets, eligible edition parsing, Setup result-code classification, VHD mount arguments, split-set completeness/identity, conversion-template copying, verified download bytes, checksum mismatch cleanup, hostile redirects and cancellation. A Windows x64 cross-build completed successfully. None of these checks executes Windows servicing, real Microsoft media downloading, Windows Setup or an upgrade.

## Required Windows validation

1. Confirm no log/code pane is present. Exercise loading, saving, conversion and ISO creation; the footer and active edition rows should show genuine percentage progress when provided, otherwise an indeterminate indicator. Help should open the private diagnostics folder. Failed tools must not dump their raw output into the main UI.
2. Generate an official Microsoft URL and hash for the same release/language/architecture. Download a real ISO/ESD, compare its SHA-256 independently, and exercise cancellation, an expired URL, a mismatch, an existing output path, disk-full handling and a network interruption.
3. Load an ESD and a complete SWM set. Verify only the selected edition is prepared in a writable cache before mount. Export all editions, compare names/indices, and confirm originals are unchanged. Check missing/mixed parts are refused. Exercise a failed export and inspect its retained private partial file.
4. Delete an unwanted edition from an expendable multi-edition WIM; compare the resulting inventory. The final edition must be protected. Export to reclaim unused resources. Read and apply one genuinely eligible offline edition upgrade, then validate its servicing state and licensing separately.
5. Convert an install image to ISO with matching setup media. Verify the template's old install image is excluded, the selected/all editions are exported as install.wim, setup/boot files remain, and the final ISO boots/installs in disposable BIOS and UEFI VMs. Conversion requires separately supplied ADK oscdimg and does not certify hardware/language compatibility.
6. Inspect, mount, service, commit/discard and reconnect copied VHD and VHDX files. Compare DISM mount identities and ensure no WIM-only integrity flag is used for virtual disks. No partition-layout editing is provided.
7. On an expendable Windows VM, select This PC explicitly, review the immediate-change confirmation, and apply an applicable feature/CAB operation. Check that driver integration and client edition upgrade are refused online, and that online MSU support is restricted to Windows 11+. Observe restart-required status without an app-forced restart.
8. Select a different Windows drive root or a VHD volume assigned a drive letter. Verify its volume identity, refusal of aliases of the running volume, and refusal after drive replacement. Confirm changes are immediate and save/discard is not offered as rollback for a deployed installation.
9. Use original Microsoft setup media in a disposable Windows VM. Verify the signature check, scan result classification, blocked migration behavior, stale-media/checkbox invalidation and fingerprint checking. Only a completed pass enables interactive Setup. Cancel in Setup and verify the app does not accept terms or force an installation/restart. Test supported app/data preservation paths inside Setup, with backups.

Registry tweaks, proprietary component removal, an automatic Windows catalogue and fully unattended refresh are outside this implementation. All new Windows behavior above remains unverified in the Linux build environment. The website is validated separately at the DOM/content level; no new browser screenshot or Windows GUI screenshot is claimed.
